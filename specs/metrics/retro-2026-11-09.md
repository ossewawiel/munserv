- Why it missed: the role-check rule was missing. The last retro gave the web card its test rules, but the backend card had none. The `!!` rule existed, but the implementer did not apply it to test code.

**2. Guard holds read as red runs in the retro evidence (18 of 29 runs).**
- Sources: CI edit guard (13 runs) and Infra review guard (5 runs) on PRs 295-308. Each one printed `##[error]Held:` on purpose.
- Earliest check: `scripts/retro-gather.py`.
- Why it missed: the script lists every failed run with a 30-line log tail. It cannot tell a hold from a failure. The retro is 85% of the tick spend ($3.43 of $4.02), and these tails were about 40% of the evidence it read.
- Fix, tier 1 (script), landed: `is_hold` in `scripts/retro-gather.py` matches the runtime `##[error]Held:` line and the voided-release line. Holds appear under one "Guard holds" line per workflow, with no log tail. An API failure in a guard still shows in full. Test `case_is_hold` in `scripts/test-retro-gather.py`.
- Side fix: `sizes()` dropped every file when the script ran inside an agent worktree, because it tested the absolute path for `.claude/worktrees`. It now tests the relative path. `case_sizes` failed in the retro worktree before this change.

**3. Auto PR fails on a GitHub blip and on a draft PR (5 runs).**
