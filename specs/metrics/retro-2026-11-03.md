## Clusters

**1. Eyeball blocks the console cannot run or that cover too little (6: PRs 125, 150, 154, 156, 164, issue 240).**
- Earliest check that could catch it: the feature-planner card and the handoff template.
- Why it missed: the rule existed, but nothing enforced it.
- Fix, tier 1 (lint): `scripts/lint-handoffs.py` with `scripts/test-lint-handoffs.py`, run in the domain CI job on every handoff a branch adds.
- What the lint refuses:
  - a prose block
  - fewer than 2 or more than 6 checks
  - a missing key
  - an unknown account or service
  - a bare-path url
  - an acceptance criterion that no check lists in the new `covers` key and that `eyeball_exempt` does not list
- Template updated.
- Wrong expected values (PRs 156, 240) stay a reviewer judgement.

**2. Tests that pass without exercising what they name (4: PRs 106, 125, 135, 156).**
- Earliest check that could catch it: the web card, which had no rule for this.
- Fix, tier 3 (card): three lines in `web/CLAUDE.md` Tests.
  - A test of a write performs it with userEvent.
  - An error fixture copies the body shape the backend controller test asserts.
  - Module mock state resets in beforeEach.

**3. Visual baselines that do not show the shipped render (5, plus 4 red runs: PRs 106, 138, 220, 226).**
- Earliest check that could catch it: the web card, which named the command but not the scope.
- Fix, tier 3 (card): three rules in `web/CLAUDE.md` Tests.
  - One page shell per story.
  - Re-record all stories of a changed component.
  - Commit PNGs from the CI `visual-web-report` artifact.

**4. Three backend error body shapes (PR 125).**
- Earliest check that could catch it: CI, which had no rule.
- Fix, tier 1 (CI check): the step `One error body type in the backend` refuses a new `class ErrorResponse`.
- The two existing duplicates are allowlisted under #246.
